# 游標插入與 PDF 長字串折行（2026-10-13）

使用者指定：點選儲存格後保留內容，在游標位置插入；另外指出 PDF 長字串未折行。這是兩條獨立處理路徑，不以視覺編輯器的 CSS 折行推斷 PDF 行為。

## 游標插入

| 位置 | 行為 |
|---|---|
| VisualEditor.toolInsertionSelection | 點選文字儲存格時捕捉來源游標，選取文字也只在 active head 插入，保留前後內容 |
| 空段落 | 區塊插入重用只有空白／par 標記的段落；行內公式保留段落結構 |
| SourceView | 公式、矩陣、表格、程式碼及圖片使用共同插入位置；草稿面板沿用游標位置 |
| 上方／下方新增 | 仍使用明確 boundary，保留原操作 |
| 已有區塊／格式化內容 | 原子區塊無文字游標時保留邊界操作；行內限制防止破壞標題或格式指令參數 |

行內公式留在原段落。顯示公式、表格與程式碼保留各自 LaTeX 區塊結構，必要的 TeX 分隔不代表建立額外空儲存格。來源識別、版本及單一歷史交易仍驗證，復原可還原原始位元組。

## PDF 正文折行

packages/document-core/src/pdf-wrap.ts 僅在 document 內可辨識的 text／format 節點，為長度至少 32 的連續 ASCII 字母或數字每 16 字加入 allowbreak。公式、verbatim、註解、未知指令參數及表格原始區塊不改寫；解析超出預算時沿用原始輸入。此門檻適用一般正文，不宣稱替任意自訂 TeX 巨集或窄欄處理斷行。

FrontendCompiler 對已確認修訂的主文件產生排版副本，不改動磁碟 TeX 或編輯器文件。ManagedCompileService 把已捕捉的編譯輸入複製到私有 stage/input，保留相對目錄，逐檔驗證真實路徑、檔案身分及 SHA-256。資源不透過放寬 untrusted 旗標取得；發布前仍核對原始來源、取消及工作區歸屬。

沒有新增換行，因此來源行號保留；主文件欄位移可能改變，診斷 column 清除。私人主檔路徑轉回原檔，成功輸出的 SyncTeX 也轉回原始工作區路徑。未需正文折行的文件沿用原編譯路徑。核心函式採 Apache-2.0，Electron 整合仍在 AGPL host 範圍。
