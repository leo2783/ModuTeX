# Thanks for collaborating

Please follow the below rules. It will make our work become more clear.

---

## Development Workflow

### Create a feature branch

```bash
git checkout -b feature/your-feature-name
# or
git checkout -b fix/your-bug-fix
```

### Commit Message Format

```text
<type>: <subject>

<body>
```

**Wrong format**：

```text
<type>: <subject>
<body>
```

**Types:**

- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Formatting changes (does not affect code execution)
- `refactor`: Refactoring
- `perf`: Performance improvements
- `test`: Testing related
- `chore`: Build/tooling changes
- `ci`: handle ci things

### Branch Naming Conventions

- `feature/` - New features
- `fix/` - Bug fixes
- `hotfix/` - Emergency fixes
- `refactor/` - Refactoring
- `docs/` - Documentation updates

---

## Development Finished

When you finish developing a module, update its documentation so others can
quickly understand the changes.
